## 1. Unit tests (pure TypeScript)

- `letterbox416`: landscape, portrait, square inputs; padding bottom/right with 114; ratio correct.
- Coordinate mapping round-trip: model space → source frame normalised, boxes clipped to [0,1].

## 2. Model decoding tests

- Hand-built `[1,3549,85]` tensors: single anchor at each stride (8/16/32) decodes to the expected `cx,cy,w,h` using `cx=(raw_cx+gx)*stride`, `w=exp(raw_w)*stride`.
- Score = objectness × class; class filter keeps only COCO ids 2, 3, 5, 7; threshold edge cases.
- Per-class NMS: overlapping same-class boxes merge, different classes both kept, tie-breaking deterministic.
- Anchor count check: 52²+26²+13² = 3549.
- Golden vectors from the real model once available (needs M4), stored under `app/tests/fixtures/`.

## 3. Synthetic detection fixtures

JSON sequences of detections with known truth: a box growing at a constant rate, shrinking, static, jittering, appearing/disappearing, two crossing boxes, an occlusion gap, spurious single-frame blips, variable frame intervals.

## 4. Recorded-clip replay tests

Two replay modes: (a) detections JSON recorded from real runs fed to tracker/approach/alert on a laptop (deterministic); (b) `FileVideoSource` plays a clip through the full on-device pipeline. Clips are self-recorded or properly licensed, labelled by timestamp (events: vehicle appears, overtaking, turn, occlusion, approach start). No tuning on the held-out evaluation clips.

## 5. Tracker tests
ID persistence through a short gap (< 1.0 s), ID not reused across lost > 2.0 s, no merge of crossing tracks, tentative → confirmed after 3 hits, deleted after expiry, bounded history, deterministic output.

## 6. Approach-estimator tests
Growing box → positive growth and finite TTC proxy; static → ~0; shrinking → negative, `ttcProxyS = null`; robust to a single outlier box; low sample count → low confidence/none; frame-interval jitter; confirms output is labelled a trend (no distance field).

## 7. Alert-state transition tests
Full transition table, hysteresis (no flicker around threshold), minimum track age and consecutive-update counts, **health override** (camera/detector not `ok` → UNAVAILABLE regardless of tracks), NORMAL never emitted while unavailable, recovery path.

## 8. WebSocket protocol tests
Handshake success; wrong token (4401); no hello within 3 s (4408); binary before auth (4401); wrong origin (4403); unsupported version (4426); malformed header/`metaLen` (4400); oversize frame (1009); lockout after 5 failures (4429); viewer limit (4430); ingest replacement (4409); slow viewer never grows queues (credit window 2, newest replaces unsent); ack timeout (4440); revoke (4410); expiry (4411); reconnect with backoff; `status` cadence; `ping/pong` offset estimation; bytes forwarded unchanged.

## 9. Security tests
Viewer cannot call ingest; another app on the phone cannot use the ingest socket without the ingest token; `/ws/view` rejects missing/other origins; listener bound only to the hotspot address (verify with a connection from a non-hotspot interface, if present); no token in logs, URLs sent to the server, or crash output; no endpoint exposes video without auth; static route allow-list (no path traversal: `/../`, encoded variants); rate limits enforced; tokens differ between sessions.

## 10. Android integration tests (physical phone)
Camera permission grant/deny/revoke flows; `getUserMedia` 720p; keep-screen-on; app pause/resume behaviour (camera restart or `stalled` shown); plugin start/stop; network change handling; QR shows the right address; memory over time.

## 11. iPhone Safari tests
Loads the page over the hotspot with no internet; WebSocket binary frames render; canvas overlay scale correct; audio unlock by tap; Auto-Lock behaviour; backgrounding Safari then returning (reconnect, STALE/LOST shown); airplane-mode toggle; switching hotspots.

## 12. Physical-device performance, thermal and power tests
Measured per `DEVICE_COMPATIBILITY.md`. Always record: ambient conditions, power source, screen brightness, hotspot on/off, battery temperature (if exposed), charging state, app version/commit.
